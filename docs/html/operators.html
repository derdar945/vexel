Операторы и менеджер

Core остаётся маленьким. Возможности — операторами: функциями, значениями, объектами, событиями, нативным API.

1. Идея

Оператор — официальное расширение языка, а не «библиотека сбоку». После установки его глаголы призываются той же решёткой #, что и свои инструменты. Никаких import/include/using/require: @ и так значит «положить на скамью» — @ VexGUI кладёт оператор:

@ VexGUI
> version #
@ w : window # "Hi", 400, 300

2. Формат operator.vxop

Плоские строки key = value, комментарии #/;, кавычки для значений с пробелами, неизвестные ключи игнорируются (задел на будущее):

# VexGUI — official Vexel GUI operator (native, Win32)
name = VexGUI
version = 1.0.0
description = Lightweight native windows, text, buttons and inputs
type = native
vexel_version = 0.1.0
platform = windows
architecture = any
entry = VexGUI.dll
provides = version/0, window/3, show/1, open/1, close/1, run/2
dependencies = VexNet >= 1.0

3. Хранилище

Установленное лежит в <каталог exe>/operators/<Имя>/ (манифест + DLL). Переменная VEXEL_OPS переопределяет путь — так изолируются тесты. Источники для установки: ./operators/Имя и ./Имя относительно текущей папки.

4. Установка и зависимости

!vex_add VexGUI делает по порядку:

  1. читает манифест источника, сверяет имя;
  2. проверяет Core (Operator ABI mismatch: … wants vexel >= …), платформу, архитектуру;
  3. ставит зависимости вглубь: каждая сверяется по semver (>= == > <= < !=), недостающая тянется из тех же источников;
  4. копирует манифест + DLL в хранилище, печатает протокол [OK].

Ошибки — словами из ТЗ:

Operator not found: Nope
Missing dependency:
VexNet >= 1.0
Circular dependency: CycleA -> CycleB -> CycleA
Недокат вытирается: каталог в хранилище удаляется при любой ошибке после создания. Установка поверх checkout-разработки, который И ЕСТЬ запись хранилища, источники не трогает (сравнение канонических путей).

!vex_remove отказывает, пока оператор кому-то нужен; !vex_update — переустановка из источников.

5. Загрузка в рантайме

Строка @ Имя компилируется в VX_ATTACH: LoadLibrary, поиск экспорта vxop_open, сверка ABI-номера и пары имя+версия с манифестом. Призывы — VX_CALL_OP (ссылка оператор/глагол/арность). Библиотеки выгружаются при смерти VM. Байткод с операторами — .vxb VXB2 (несёт таблицу операторов); старые VXB1 грузятся как раньше.

Свой оператор за 6 шагов

Создание → API → код → сборка → установка → использование.

1. Создание

!vex_operator_new MyOp

Получаешь MyOp/operator.vxop, src/MyOp.c (рабочий глагол ping/1), examples/hello.vx, README. Имя — латиница/цифры/подчёркивание.

2. API сначала

Придумай глаголы и арности, запиши в манифест — компилятор будет проверять каждый призыв:

provides = ping/1, shout/1

3. Код

#include "operator.h"

static int op_shout(const VxOpApi *api, VxOpVal **args, int argc,
                    VxOpVal **out) {
    const char *s = NULL;
    size_t n = 0;
    if (!api->as_text(args[0], &s, &n)) return 1; /* -> fail */
    /* ... собрать LOUD ... */
    *out = api->make_text(LOUD, LOUDN);
    return *out ? 0 : 1;
}

static const VxOpFuncInfo funcs[] = {
    { "ping", 1, op_ping },
    { "shout", 1, op_shout },
};

VXOP_EXPORT const VxOpInfo *vxop_open(const VxOpApi *api) {
    static VxOpInfo info;
    (void)api;
    info.abi_version = VXOP_ABI_VERSION;
    info.name = "MyOp";          /* == manifest */
    info.version = "0.1.0";      /* == manifest */
    info.nfuncs = 2;
    info.funcs = funcs;
    return &info;
}
Три запрета: не трогать значения мимо api; не отдавать указатель args (только свежее через конструкторы/clone); не забывать VXOP_EXPORT, иначе загрузчик не найдёт vxop_open.

Нужен Vexel, решающий по событию (как шаг GUI)? api->summon("step", NULL, 0, &r) + api->is_true(r) — подробности в ABI.

4. Сборка

!vex_operator_build MyOp

Собирает src/*.c в MyOp/MyOp.dll через gcc и Core-include/ (ищется вверх от каталога). Нужен gcc на PATH.

5. Установка

!vex_add MyOp

Проверяются манифест, версия Core, платформа, наличие DLL, дерево зависимостей. Типичные отказы — Missing dependency:, Operator ABI mismatch, Native module not built.

6. Использование

@ MyOp
> shout # "tide"
> shout # 42 ?? "loud words only"

Призывы со скамьи

Как код Vexel пользуется операторами: разрешение имён, арность, ошибки, байткод.

1. Привязка

@ VexGUI
@ w : window # "Hi", 400, 300
> show # w

Строка @ Имя (без двоеточия!) стоит сама по себе — только верхний уровень, выполняется по порядку. Компилятор читает установленный манифест и запоминает глаголы с арностями; VM грузит DLL в момент выполнения строки.

2. Порядок разрешения

Для имя # args компилятор смотрит по очереди:

  1. свои & инструменты (они всегда главные);
  2. глаголы привязанных операторов (первый привязанный побеждает при споре имён);
  3. встроенные len/at/type/str.

3. Ошибки — громкие, с координатами

vexel: 1:1: unknown operator '@ Nope' — install it first (!vex_add Nope)
vexel: 2:3: 'window' wants 3, summoned with 1
vexel: Failed to load Operator: Demo
Reason: cannot open Demo.dll (code 126)

4. Результаты — обычные значения

Ответ оператора — первоклассное значение: в ячейку, в инструмент, в сравнение, под якорь:

@ VexGUI
@ b : button # w, "OK", 20, 60
> close # 999 ?? "no window"
? clicked # b :
  > "pressed"
.
Хендлы GUI — обычные числа. Мёртвые хендлы: open читает мёртвое окно как 0 (круги приземляются мягко), остальные глаголы поднимают fail — лечится через ??.

5. Байткод

VX_ATTACH op — положить (LoadLibrary + vxop_open + сверка личности). VX_CALL_OP ref — призвать (снять аргументы, вызвать C-функцию, положить ответ или fail). Дизассемблер (!vex_check -v) показывает таблицу операторов и ссылки.
